## 1. Установка Git

1. Скачан установщик Git for Windows `F:\Git-2.56.0.4-64-bit.exe` (материал: https://gitforwindows.org/).
2. Установка выполнена в тихом режиме без изменений диска C:

   ```powershell
   Start-Process -FilePath 'F:\Git-2.56.0.4-64-bit.exe' `
     -ArgumentList '/VERYSILENT','/NORESTART','/SP-','/CLOSEAPPLICATIONS','/DIR=F:\Git','/LOG=F:\labagit\git_install.log' -Wait -PassThru
   ```

3. Проверка установки:

   ```
   F:\Git\cmd\git.exe --version
   git version 2.56.0.windows.4
   ```

## 2. Создание локального репозитория

1. Перешли в папку проекта `F:\labagit` (она была создана заранее).
2. Инициализировали репозиторий с основной веткой `main`:

   ```
   git init -b main F:\labagit
   Initialized empty Git repository in F:/labagit/.git/
   ```

3. Настроили имя и e-mail **локально** (только для этого репозитория, без записи в глобальный конфиг на диске C:):

   ```
   git config user.name "Oleg Zvalinskiy"
   git config user.email "student@example.com"
   git config core.autocrlf false
   ```

4. Проверка состояния:

   ```
   git status --short --branch
   ## No commits yet on main
   ```

## 3. Создание файла отчёта и первой версии в Git

1. Создан файл `Отчет_по_практической_работе_7.md` с описанием выполненных шагов.
2. Файл добавлен в индекс и зафиксирован первой версией (коммитом):

   ```
   git add .
   git commit -m "Initial report: install Git and create local repository"
   ```

3. Проверка истории (первая версия отчёта зафиксирована):

   ```
   $ git log --oneline
   7182816 (HEAD -> main) Initial report: install Git and create local repository
   ```

   Коммит — это снимок состояния файлов в репозитории. Команда `git add .` помещает изменения в область подготовки (index), а `git commit` создаёт версию с уникальным хешем `7182816`.

## 4. Ветка отчёта

Материал: https://habr.com/ru/post/342116/

1. Создана ветка `report-branch` от текущей версии `main` и выполнен переход в неё:

   ```
   git checkout -b report-branch
   Switched to a new branch 'report-branch'
   ```

2. В отчёт добавлены развёрнутые описания шагов: что делает каждая команда (`git add`, `git commit`, `git log`), как устроена область подготовки и для чего нужны ветки.
3. Изменения зафиксированы новой версией отчёта **в ветке** `report-branch`:

   ```
   git add Отчет_по_практической_работе_7.md
   git commit -m "Add detailed step descriptions in report branch"
   ```

4. Проверка истории ветки:

   ```
   git log --oneline --decorate
   ```

## 5. Слияние ветки с основной

1. Выполнен возврат в основную ветку:

   ```
   git checkout main
   Switched to branch 'main'
   ```

2. Ветка отчёта слита в `main` с созданием явного коммита слияния (`--no-ff`), чтобы история сохраняла информацию о ветке:

   ```
   git merge --no-ff report-branch -m "Merge report-branch into main"
   ```

3. После слияния последнее изменение отчёта находится в основной ветке:

   ```
   git log --oneline --decorate --graph
   ```

4. Ветка `report-branch` оставлена в истории как отметка о проделанной работе.

## 7. Статический сайт на GitHub Pages

Материал: https://htmlacademy.ru/blog/git/github-as-hosting

1. В папке `docs/` создан простой статический сайт: `index.html`, `css/style.css`, `js/script.js` и `README.md`. Страница содержит заголовок, описание, кнопку с обработчиком JavaScript и адаптивные стили.
2. Локальная проверка: файл открывается в браузере, кнопка выводит ответ.
3. Публикация выполняется через **Settings → Pages → Deploy from a branch → main / docs**. GitHub Pages берёт файлы из папки `docs` основной ветки.
4. Адрес опубликованного сайта: `<логин>.github.io/<имя-репозитория>/` (уточняется после публикации).

## 8. Динамический сайт на GitHub (доп. задание)

Материал: https://habr.com/ru/post/458006/

1. В папке `dynamic-site/` создано приложение на Flask:
   - `app.py` — маршрут `/`, приветствие по имени из формы, серверное время и счётчик посещений;
   - `templates/index.html` — шаблон, который рендерится на сервере;
   - `static/style.css` — стили;
   - `requirements.txt`, `render.yaml`, `README.md` — зависимости, конфигурация хостинга и инструкция.
2. Проверка локально через тестовый клиент Flask: `GET /` → 200, `POST /` с именем → 200 и приветствие «Привет, Олег!».
3. GitHub Pages поддерживает только статические файлы, поэтому исходники динамического сайта размещены в репозитории `homework IIT` в папке `dynamic-site/`, а для реального запуска описано развёртывание на Python-хостинге (Render/PythonAnywhere).
