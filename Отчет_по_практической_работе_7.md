
## 3. Создание файла отчёта и первой версии в Git

1. Создан файл `Отчет_по_практической_работе_7.md` с описанием выполненных шагов.
2. Файл добавлен в индекс и зафиксирован первой версией (коммитом):

   ```
   git add .
   git commit -m "Initial report: install Git and create local repository"
   ```

3. Проверка истории (первая версия отчёта зафиксирована):

   ```
   $ git log --oneline
   7182816 (HEAD -> main) Initial report: install Git and create local repository
   ```

   Коммит — это снимок состояния файлов в репозитории. Команда `git add .` помещает изменения в область подготовки (index), а `git commit` создаёт версию с уникальным хешем `7182816`.

## 4. Ветка отчёта

Материал: https://habr.com/ru/post/342116/

1. Создана ветка `report-branch` от текущей версии `main` и выполнен переход в неё:

   ```
   git checkout -b report-branch
   Switched to a new branch 'report-branch'
   ```

2. В отчёт добавлены развёрнутые описания шагов: что делает каждая команда (`git add`, `git commit`, `git log`), как устроена область подготовки и для чего нужны ветки.
3. Изменения зафиксированы новой версией отчёта **в ветке** `report-branch`:

   ```
   git add Отчет_по_практической_работе_7.md
   git commit -m "Add detailed step descriptions in report branch"
   ```

4. Проверка истории ветки:

   ```
   git log --oneline --decorate
   ```

## 5. Слияние ветки с основной

1. Выполнен возврат в основную ветку:

   ```
   git checkout main
   Switched to branch 'main'
   ```

2. Ветка отчёта слита в `main` с созданием явного коммита слияния (`--no-ff`), чтобы история сохраняла информацию о ветке:

   ```
   git merge --no-ff report-branch -m "Merge report-branch into main"
   ```

3. После слияния последнее изменение отчёта находится в основной ветке:

   ```
   git log --oneline --decorate --graph
   ```

4. Ветка `report-branch` оставлена в истории как отметка о проделанной работе.
